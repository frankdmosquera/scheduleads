From the project plan

1 · Problem
The agency promises "nothing rented" and every site it ships rents booking from Calendly or Cal.com. Small service businesses stitch together a booking tool, a contact form that emails into a void, a CRM they never open and a Google listing with the wrong hours. Scheduleads is the CRM that owns the journey from "I found you" to "the job is done and paid," starting with the booking.
2 · Users
The owner/operator, who wants to know who booked and where every lead stands. The customer, who books on the business's own site and never sees the product's name. Frank in two hats: organization number one, and the platform admin behind the admin role. Crew members and self-serve customers later. Tenants in order: agents-web, Primo Painters, Face and Body, The Latam Painters.
3 · Features
One app, three parts kept separate in code: the booking module a client site imports, the CRM login (leads, pipeline board, email, settings, later crews and reports), and the admin area. Nine phases: foundation, the booking loop, the agency site wired, CRM first release, Primo, CRM second release, every client, the CRM grows, packages and self-serve.
4 · Data
Better Auth's organization tables plus booking_link, availability_rule and calendar_connection carried from the first repo. contact, lead and booking as locked shapes. New from item 4: pipeline_stage, resource and activity, so stages, capacity and the timeline are tables from the start. Every table organization-scoped from the session, never the client.
5 · Tech
Next.js 16 frontend on Vercel, Hono API on Railway, Postgres with Drizzle, packages/shared for the schema and the API contract. Better Auth with the organization, emailOTP and admin plugins. Resend, Google Calendar free/busy, Twilio. TanStack Query, dnd-kit and shadcn charts arrive at the features that need them, asked first.
6 · Monetize
Agency-provisioned first. Booking sits in the $240/mo plan, the first rung of a ladder of packages. Each rung unlocks modules through the plan-limits config, and the gate exists from item 1 so nothing is retrofitted. Primo pays the first rung; the clinic pays cost-cover. Off-page SEO stays Frank's work; the tool reports it. Stripe self-serve is Phase 9.
7 · UI/UX
The widget is an unstyled trigger plus a modal themed by the host site, and the modal never names its provider. The login is the CRM, with Pipedrive and Salesmate as the reference feel. Static mockups come first in item 0b: the modal in the agency's and Primo's themes, the leads list, the board and settings. No UI feature is specced before they exist.
8 · Deployment
frontend to Vercel, backend and Postgres on Railway, all already provisioned. CORS allow-list from WIDGET_ORIGINS; browser-to-API or proxied through the host is decided in Phase 3. Google OAuth stays in Testing until Phase 9; Gmail's restricted scopes need verification plus a security assessment. Losing CALENDAR_TOKEN_KEY breaks every stored calendar connection.

Locked decisions

  • Every app table is organization-scoped and the scope is a security boundary. organizationId comes from the session on the server, never from a client.
  • availability_rule is org-scoped, not per booking link. Per-resource hours come later on top of it.
  • pipeline_stage, resource and activity are tables from item 4 onward, never enums.
  • Tenant code never reads across organizations and never asks "is this the agency." The agency's own organization gets no special case.
  • The package gate reads organization.plan from item 1. Rungs above agency are a config edit, not code.
  • Email is send-only plus BCC capture first. Two-way Gmail sync waits for Google's restricted-scope verification.
  • The modal never names its provider and the host's buttons say "Book now."
  • No feature that renders UI gets specced before the item 0b mockups exist.
  • A failed calendar check never reports "free."
