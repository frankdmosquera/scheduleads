Private data and caching

Settled during your folder walkthrough on Sep 23. The rule: one person's data is never kept anywhere another person could see it. Written here so it can be reread, not relearned.

The risk
Browsers save copies of what servers send, so Back feels instant. On a shared front-desk computer, the next person could press Back after sign-out and see the previous owner's business, without the server ever being asked. Two ways it can happen: the browser reuses a saved API answer, or it restores a frozen snapshot of the whole page.
Browser cache
Every signed-in API answer carries Cache-Control: no-store: "never keep a copy". Set once by the dashboardNoStore middleware in backend/src/server.ts, which stamps the header after await next(), on the finished response. That forces the browser to really ask the server, which refuses someone who is signed out. Done and proved.
Page snapshot
The header above cannot stop a frozen page coming back, because the page comes from Next, not from the API. Sign-out must leave nothing behind: clear React Query's cache and leave with window.location.replace("/sign-in") so Back has no dashboard to return to. Not yet tested. That is W16, run with the parked end-to-end sign-in check.
React Query cache
Lives in the dashboard's memory and belongs to our own code. Shows cached data instantly and checks the server at the same moment. Cleared on sign-out and on switching business. Settings for it are in the coding standards, under Data Fetching.
Next's server cache
Not used. The dashboard is an app behind a login, so it fetches in the browser and never on the Next server. A server-side fetch can run once at build time and bake one moment's data into the page, which is the static-site trap.
Full-stack Next, for reference
Private pages that read the session are protected automatically. API route handlers are on you: return Cache-Control: no-store yourself. Server Actions need nothing, because they are always POST and a POST answer is never cached. headers() in next.config.ts is only for special cases, such as a static page that must not be kept.

// Minutes count from midnight in the business's time zone, so 570 is 9:30.

import { z } from "zod";

const MINUTES_IN_A_DAY = 1440;

export const timeWindowValidationSchema = z
  .object({
    startMinute: z.int().min(0).max(MINUTES_IN_A_DAY),
    endMinute: z.int().min(0).max(MINUTES_IN_A_DAY),
  })

  (windows) => {
    const sorted = [...windows].sort((a, b) => a.startMinute - b.startMinute);
